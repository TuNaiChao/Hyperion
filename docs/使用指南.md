# bug-RCA 使用指南(在 opencode 上)

> 面向**使用者**(给人读的操作指南,可详细解释)。skill/prompt 本身的设计见 [02-bug-rca.md](设计/harness-v2/02-bug-rca.md);skill 源文件 [.claude/skills/bug-rca/SKILL.md](../.claude/skills/bug-rca/SKILL.md)。
>
> bug-RCA 现在是「**工具箱 + 人在环迭代**」:opencode 加载 bug-rca skill + 调 8 个 Hyperion MCP 工具,自驱定位根因 + 改代码 + 落盘补丁;**你拿补丁到真机/复现环境验证**,通过才沉淀记忆 + 报告。

---

## 0. 前置:安装 opencode.json(关键,最容易踩的坑)

⚠️ **opencode 启动时从当前目录向上找 `opencode.json` —— 它默认不认 `config/opencode_hyperion.json` 这个文件名。** 模板在 [config/opencode_hyperion.json](../config/opencode_hyperion.json),但必须"安装"成**项目根的 `opencode.json`** 才会被 opencode 识别(否则你看不到 hyperion MCP、也选不到 hyperion-bug-rca agent)。

```bash
# 在项目根执行:拷贝模板 + 注入你的仓库名到 HYPERION_CODEBASE
python -c "
import json
d = json.load(open('config/opencode_hyperion.json'))
d['mcp']['hyperion']['environment']['HYPERION_CODEBASE'] = '<你的仓库名>'   # 例:'wpa'
json.dump(d, open('opencode.json','w'), ensure_ascii=False, indent=2)
print('opencode.json 已安装')
"
```

> **`HYPERION_CODEBASE` 是什么**:告诉 Hyperion MCP server 查哪个仓库的索引/记忆(= LanceDB 表名 + memory scope)。必须跟建索引时用的名字一致。
>
> **为什么不直接用模板**:opencode 只认 `opencode.json`;`config/opencode_hyperion.json` 是项目存的模板(含 `mcp` 段 + `agent` 段定义)。模板里 `environment` 默认只有 `PYTHONUNBUFFERED`,没 `HYPERION_CODEBASE`(因为仓库名因人而异)→ 安装时注入。

**验证安装成功**(应能看到 hyperion-bug-rca agent):
```bash
opencode agent list        # 列表里应有 hyperion-bug-rca / hyperion-localize / hyperion-repair
```

## 1. 前置:建代码索引(一次性)

```bash
uv run hyperion index <仓库路径> <名字>     # 例:hyperion index example/demo2/wpa wpa
```
> `search_codebase` / `blast_radius` 要用索引;`filter_logs` / `recall` / `validate_patch` / `export_patch` 不需要。

## 用法 A:交互式 TUI(推荐 —— 人在环天然,适合迭代)

### A.1 启动 TUI
```bash
opencode                   # 在项目根(opencode.json 所在目录)启动交互式 TUI
```

### A.2 选 hyperion-bug-rca agent
TUI 里切到 bug-rca agent —— 它配置成 `mode: primary`,跟 opencode 内置的 Build/Plan 并列:
- 按 **Tab** 键循环切换 primary agent,切到 `hyperion-bug-rca`;或
- 敲 `/` 看斜杠命令列表,找 agent 相关命令(不同 opencode 版本入口略异,`/help` 可查)。

> 看不到这个 agent?→ 回到第 0 步:项目根必须有 `opencode.json`(不是 `config/opencode_hyperion.json`),`opencode agent list` 能看到才算装好。

### A.3 对话(你输任务,agent 干活,你实时看)
切到 hyperion-bug-rca 后,输入框敲:
> 我在 wpa_supplicant 有个 bug 要定位根因 + 修复:WiFi 扫描不到(持续 ssid-not-found / association took too long,重启 wpa_supplicant 才恢复)。日志 `example/demo2/journalctl_b.txt`(1.6 万行,用 filter_logs 按故障时间窗筛,别读全量)。代码仓 `example/demo2/wpa`。

agent 自驱:加载 bug-rca skill → 按需调 `recall` / `search_codebase` / `filter_logs` / `blast_radius` → 立根因 + 主动证伪 → `edit` 改代码 → `validate_patch` → `export_patch` 落盘。**TUI 实时显示它调的每个工具和结果**,你看着它干活。

### A.4 人在环验证(交互式的核心优势)
agent 落盘补丁(`data/bug_rca/<repo>.patch`)后,你拿去真机/复现环境验证,然后**直接在同一个对话框**反馈:

- **没修对** → 输:`补丁在真机上没修对,现象是 X。重新定位——会不会 scan_res_handler 被并发请求覆写、结果误路由到 scan_only_handler?` → agent 回头改、再 `validate_patch` / `export_patch`。
- **修对了** → 输:`补丁验证通过了。memorize + export_report 收尾。` → agent 沉淀记忆 + 写报告。

> 交互式**不用退出 TUI、不用续 session** —— 你就在环里,随时纠偏/反馈。这是工具箱+人在环范式的理想形态(比脚本式 `run` 自然得多)。

## 用法 B:非交互 `opencode run`(脚本 / e2e / CI 用)

```bash
opencode run --agent hyperion-bug-rca --model uniontech-ai/glm-5.2 \
  --format json --print-logs \
  "<bug 现象 + 故障日志绝对路径 + 代码仓绝对路径>"
```
- 跑完取 `data/bug_rca/<repo>.patch` 去验证。
- 验证后用 `opencode run --continue ...`(续上个 session)反馈结果,让 agent 收尾或续修。

> `--format json --print-logs`:输出 JSON 事件流 + 日志到 stderr,便于脚本解析(看工具调用)。交互调试去掉这俩。

## 产物

| 文件 | 何时有 | 路径 |
|---|---|---|
| 补丁 | 每版都落盘(覆盖,最新为准) | `data/bug_rca/<repo>.patch` |
| 报告 | **验证通过后**(agent 收尾) | `data/bug_rca/<repo>-rca.md` |
| 记忆 | **验证通过后**(`memorize`) | 记忆库(kind=bug_lesson) |

## 关键提醒(必读)

1. **`validate_patch` 只验补丁能 apply,不验修对。** 系统软件通常无单元测试,**真机/复现是唯一 oracle**。每版补丁都要人验证。
2. **`memorize` / `export_report` 验证通过后才做。** 没验证就 memorize = 把没坐实的根因写进记忆,污染下次同类 bug 的 RCA。
3. **别盲信 agent 的根因。** glm-5.2 有系统性确认偏差(踩坑 #11:demo2 连续 4 次误诊 abort-fail,真因是更早的 scan_res_handler 误路由)。它立根因后,你**主动追问**:`你查了故障时刻之前的日志吗?scan_only_handler 那条 'Scan-only results received' 看了吗?是不是误路由?` —— 交互式你能即时纠偏,这是它比脚本式强的地方。
4. **`opencode.json` 陷阱**:opencode 只认这个文件名;`config/opencode_hyperion.json` 是模板,不安装看不到 agent/MCP(第 0 步)。

## 排查

| 现象 | 原因 / 解法 |
|---|---|
| TUI 选不到 hyperion-bug-rca agent | 项目根没有 `opencode.json`(只有模板);跑第 0 步安装。`opencode agent list` 验证。 |
| `opencode agent list` 里没有 hyperion-* | `opencode.json` 没在当前目录或格式错;确认在项目根、`agent` 段含 hyperion-bug-rca。 |
| agent 不调 hyperion_* 工具(裸 grep) | MCP 没连上:`opencode.json` 的 `mcp.hyperion` 段要在;`hyperion mcp serve` 要能跑(`uv sync --extra mcp`);timeout 要 ≥120000(踩坑 #10)。 |
| 工具首次调用超时 | embedder 冷启(sentence-transformers ~1.2GB);`timeout` 要 ≥120000ms(模板已设)。 |
| 补丁 apply 过但真机没修对 | 正常 —— apply 过 ≠ 修对(见关键提醒 1);迭代改 + 再验证。 |
| agent 把没验证的根因 memorize 了 | 违反新范式;交互式里你抢在它 memorize 前说"先别记,我去验证",或验证后让它改记忆。 |
