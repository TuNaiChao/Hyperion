# Multica 架构总览

> 源码锚点 `v0.4.31-2-g8c9b7503a`;file:line 相对 `multica/`。Go 侧全部在 `server/`(单模块
> `github.com/multica-ai/multica/server`,go 1.26.6,1442 个 .go 文件其中 806 个测试)。

## 一、可部署组件与拓扑

| 组件 | 位置 | 技术 | 职责 |
|---|---|---|---|
| 云 API server | `server/cmd/server` | Go:chi v5 + gorilla/websocket + pgx/pgxpool + go-redis + sqlc | REST + 两条 WS 平面;任务队列/调度;集成(Slack/Lark/Telegram/GitHub) |
| CLI + daemon(同一二进制) | `server/cmd/multica` | Go:cobra | `multica daemon start` fork 自身进后台;CLI 直连同一 REST 面(main.go:26-115) |
| 桌面端 | `apps/desktop` | **Electron 39** + electron-vite + React Router 7;打包 `multica` CLI(bundle-cli 脚本) | 桌面 App 自动把本机注册成 runtime |
| 网页端 | `apps/web` | Next.js 16 App Router + fumadocs + TanStack Query + zod | 浏览器客户端 + 文档站 |
| 移动端 | `apps/mobile` | Expo ~55 / React Native(iOS 优先) | 手机客户端 |
| 共享 TS 包 | `packages/{core,ui,views,plugin-sdk}` | TS | core = 三端共享类型(镜像 `pkg/protocol` 事件)+ API client + ws-client |
| self-host | `docker-compose.selfhost.yml` | postgres(pgvector:pg17)+ backend + frontend(GHCR 镜像) | `make selfhost` 一键;`multica setup self-host` 引导 |

三个传输平面(`server/cmd/server/router.go`,2352 行路由表):

1. **REST(chi)** —— 用户面 `/api/*`(middleware.Auth + 工作区角色卫兵,router.go:1382-1470)、daemon 面 `/api/daemon/*`(:1295-1346)、插件面 `/api/v1/plugin`(:1366-1378)。
2. **客户端 realtime WS** `/ws`(router.go:1205-1208)→ `internal/realtime` 房间模型,issue 时间线实时更新。
3. **daemon 控制 WS** `/api/daemon/ws`(router.go:1301)→ `internal/daemonws` hub;服务端→daemon 只推**唤醒提示**,真正的领取走 HTTP/RPC claim —— 「WS 提示是 advisory,HTTP claim 才是 source of truth」(hub.go:185-186)。

可选 Redis relay(REDIS_URL):多 API 节点时 realtime 事件经 Redis Streams 分片扇出,单节点纯内存(cmd/server/main.go:344-445)。

## 二、端到端数据流(issue → 设备 → issue 时间线)

```
用户在 App/网页建 issue 并指派 agent
  └─ POST /api/workspaces/{id}/issues
      TaskService.enqueueIssueTask (internal/service/task.go:1090)
        INSERT agent_task_queue (status='queued') + bus.Publish(task:queued)
        daemonHub.NotifyTaskAvailable(runtime_id)  ← WS 唤醒提示(尽力而为)
             │
设备 daemon pollLoop (internal/daemon/daemon.go:4662) —— 本地槽位信号量(MaxConcurrentTasks)
  runBatchPoller (:4720):有空槽才去领 —— "slot-before-claim",领到的任务必有本地容量(:4711-4715)
    ├─ WS RPC "tasks.claim" (internal/daemon/wsrpc.go:315-380)
    └─ HTTP 兜底 POST /api/daemon/runtimes/{id}/tasks/claim
        ClaimAgentTask SQL: queued→dispatched,FOR UPDATE SKIP LOCKED
        (pkg/db/queries/agent.sql:722-772) + 铸 mat_ 任务 token
  handleTask (:4990): POST /tasks/{id}/start → running
  runTask (:6308): 拉起 agent CLI(见 02 文档)+ 注入 MULTICA_TOKEN=mat_… 等 env
  运行中: POST /tasks/{id}/progress|messages|usage —— 执行日志逐条回传
  收尾: POST /tasks/{id}/complete|fail —— 失败自动生成重试子任务(CreateRetryTask, agent.sql:510+)
             │
每次状态迁移发布 task:* 事件 (pkg/protocol/events.go:34-42)
  → realtime hub → 浏览器/桌面 WS 帧 → issue 时间线与看板实时更新
```

claim SQL 里三个关键约束(agent.sql:733-770):runtime 在线且心跳新鲜;**同 (issue, agent) 串行**(一个
agent 在一个 issue 上同时只有一个活动任务);按 `priority DESC, created_at ASC` 排序。

## 三、daemon ↔ 云协议(internal/daemonws + pkg/protocol)

- Hub 按 runtime/workspace/user 三张索引表管理连接(hub.go:186-203);ping/pong 54s/60s;发送缓冲 16
  帧满即踢慢客户端(hub.go:457-483)。
- 服务端→daemon 帧均为提示类:`daemon:task_available`(领任务唤醒)、`daemon:runtime_profiles_changed`、
  `daemon:pending_work`(心跳捎带的请求,如模型列表发现,protocol/events.go:144-158)。
- daemon→服务端:`daemon:heartbeat` → `daemon:heartbeat_ack`(捎带待办请求);通用
  `daemon:rpc_request/response`(带 request_id/method/TimeoutMs,hub.go:761-808),每连接在飞 RPC 信号量 8。
- **防双领**:WS RPC「已发出但结果未知」时禁止立即 HTTP 兜底领同一个任务(wsrpc.go:22-32, 350-364)。
- 重连:daemon 侧 1s→30s 退避(wakeup.go:36-63);读上限 64 MiB(claim 响应最多带 32 个任务全量)。

## 四、任务管线

- **状态机**:`queued → dispatched → running → completed | failed | cancelled`,外加
  `waiting_local_directory`(local_directory 被占,migration 109)和 `deferred`(定时/频道任务,migration 255)。
- **并发两层**:服务端 per-(issue,agent) 串行(claim SQL)+ daemon 侧槽位信号量;agent 行自带
  `max_concurrent_tasks`(默认 1,migrations/001_init.up.sql:45)。
- **重试**:失败同事务插 `retry_of_task_id` 子任务,继承归因/会话策略,可选退避 fire_at;**中毒 session
  黑名单**让重试不继承坏会话(agent.sql:946-974)。
- **兜底巡检**(cmd/server/runtime_sweeper.go,30s 一轮):心跳过期的 runtime 标离线;dispatched 300s
  超时失败;running 任务墙钟 **AND 门控 daemon 存活**(数小时健康长跑不被误杀,MUL-4107);断网 3h 宽限;
  离线 runtime 7 天后 GC。
- **拒绝词表**:internal/dispatch/reason.go 是刻意设计的叶子包,稳定 ReasonCode(`runtime_offline` /
  `runtime_unusable` / `agent_runtime_required` / `quota_exceeded` …),客户端可本地化、不泄漏私有 agent 存在性。

## 五、数据层

- **sqlc** + pgx/v5:查询在 `server/pkg/db/queries/*.sql`(49 个文件),生成物 `pkg/db/generated`;迁移
  001..376 全部带 .up/.down,`cmd/migrate` 自带并发/冗余索引/重试测试。
- **核心表**(001_init):`workspace` + `member`(owner/admin/member)、`agent`(runtime_mode
  local/cloud;visibility workspace/private)、`issue`(多态 assignee member|agent)、`comment`
  (author_type member|agent;类型含 progress_update/system)、`agent_task_queue`。
- 值得注意的后续表:`agent_runtime`(004,机器×provider 实例,UNIQUE(workspace,daemon,provider))、
  `daemon_token`(029)、`task_token`(108,绑定 (task,agent,workspace,user) 四元组)、
  `runtime_profile`(120,用户自定义 agent CLI,protocol_family CHECK 与 pkg/agent 的 switch 锁步)、
  `chat_session`、`autopilot*`、`plugin_*`(安装/密钥/MCP 审批/调用)、`squad*`、`skill*`。
- **ID 策略**:应用层铸 **UUIDv7**(pkg/dbid/dbid.go:1-58)保 B-tree 局部性,明确「不用作密钥/租约」;
  ULID 只给 relay 节点/事件 id。

## 六、鉴权与多租户

- **四族 token**(internal/middleware/daemon_auth.go:79):
  - `mul_` 用户 PAT;`mdt_` daemon token(workspace+daemon 域,哈希落库);
  - `mcn_` 云节点 PAT(外部 Fleet 服务校验,配 internal/cloudruntime 云 runtime 供给);
  - `mat_` **任务级 token**——claim 时铸造,四元组绑定,注入子进程作 `MULTICA_TOKEN`:运行中的 agent
    只能以「该任务」身份回写(发评论等),不能冒充用户或别的 agent;嵌套 `multica` CLI 调用经 workdir
    标记自动改用任务 token(daemon.go:151-171)。
- JWT HS256,模板自带的秘密在 denylist,production 无 JWT_SECRET 直接拒绝启动(main.go:258-285)。
- 多租户 = workspace + member 角色,chi 中间件逐路由卫兵;realtime 订阅按 scope 逐个鉴权(ScopeAuthorizer)。

## 七、realtime 与事件

- internal/events:进程内同步 pub/sub,panic 恢复,「订阅者先于通知者」的顺序契约(main.go:463-468)。
- internal/realtime:scope 房间模型;首个/末个订阅者回调驱动 Redis relay 按需启停;多节点走分片
  Redis Streams(回放宽限/裁剪/TTL,main.go:81-97)。
- 出线卫生:listeners.go:15-68 剥离内部字段(prev_description、任务错误文本)再扇出。

## 八、Go 之外的显眼件

- **plugin 体系**:Go 侧 `pkg/plugincontract/manifest.go` 是权威契约——Action(插件→Multica)/
  Hook(Multica→插件,触发 ui/manual/agent/event,传输 http 或 **mcp**)/Resource(静态 skill 文本);
  闭合 scope 列表(issues:read/write、storage:user|workspace、net:<domain>…)同时约束 iframe CSP 与
  hook 主机。插件贡献的 MCP 工具需显式审批(plugin_mcp_approvals)。
- **pkg/llm**:openai-go 薄封装,只服务辅助层(chat 自动起标题、快捷回复生成),**不在 agent 执行路径
  上**(agent 用自己的 CLI 凭据);未配置则零上游请求, ErrNotConfigured(client.go:99-104)。
- **featureflag**:Fowler 式 Toggle Point/Router/Configuration;含单向 rollout 门
  (`custom_issue_statuses`,keys.go:27-43)与「永久开启的兼容键」照顾旧桌面端。
